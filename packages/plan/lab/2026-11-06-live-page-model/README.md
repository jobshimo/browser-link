Reproduce: start Chrome with a separate profile and the debugging port, open the target page, read its `webSocketDebuggerUrl` from `http://127.0.0.1:9222/json/list`, run the script with that URL. `storm.html` and `settle.html` are opened as `file://` URLs. The lab extension is loaded unpacked; `drive-ext.mjs <extension-id>` opens its `lab.html` as a CDP target, triggers the run over `chrome.runtime.sendMessage`, and reads `chrome.storage.local`.

Known lab artefacts, not design findings: `lab1-run1.json` `by_method` kept counting during the navigation probes after `total` was snapshotted; `lab3-run1-storm.json` and the first run of `lab-ext` used a `requestAnimationFrame` scheduler that never flushes in a hidden tab (see v4 §4.3), fixed to `setTimeout` in the committed scripts; `lab4-run1.json` `quiet_after_ms` reflects the Node-side polling loop, not the observer.
